# AERIS · 低空任务指挥台

可独立运行的 React / TypeScript / MapLibre / Three.js 前端原型。保留 AERIS 深色菜单和仪表布局，接入工作区码道版本使用的 CARTO Dark Matter 真实地图。视觉语言参考 [HALOFLUX lab · preset A](https://ryder191.github.io/haloflux/lab.html?preset=a)，没有复制该参考站代码或素材。

此版本单独放在 `apps/console/`，避免覆盖同目录树内正在制作的 `apps/web/` 静态前端。两个应用独立启动，不要求同时运行。Node.js 依赖已经在当前电脑安装好。

2026-11-11：加入真实地图、地点定位、候选方案比较、动态事件流、雷达和新手引导。原有调度助手支持状态查询、自然语言任务草稿、实际 A\* 路线预览、地形变化影响分析和记录摘要。默认本地规则模式；模型工具调用适配已实现，真实华为云联调待配置。后端说明见 [services/assistant/README.md](../../services/assistant/README.md)。

## 启动

要求 Node.js 22.12+，以及启用 WebGL 的现代浏览器。当前电脑可以直接运行：

```powershell
cd E:\ICT大赛\lowalt-console-ui\apps\console
npm.cmd run dev -- --port 5174 --strictPort
# 或一条命令同时启动前端与助手后端（两者择一）：
npm.cmd run dev:all
```

打开 <http://127.0.0.1:5174/>。首次在其他电脑运行，先执行 `npm ci`。Windows 遇到 PowerShell 脚本策略限制时使用 `npm.cmd`。

```bash
npm run build                     # TypeScript 检查 + 静态构建，产物 dist/
npm run preview -- --port 4174     # 预览构建产物
npm test                          # Playwright 浏览器验收
node scripts/capture.mjs           # 本机 Chrome 截图，开发服务需在5174运行
```

测试默认使用本机 Google Chrome；CI 环境使用 Chromium，先执行 `npx playwright install --with-deps chromium` 并设置 `CI=true`。测试包含原控制台、助手、真实坐标保存、定位权限、地点搜索、历史方案比较、地图断网恢复和移动端布局。

## 第一次操作

1. 默认打开真实底图。拖动平移，滚轮缩放，右键旋转；顶部 2D / 3D 切换相机。“地形实验”可返回原有的本地 Three.js 地形视图。
2. 按 L 或点“地点定位”，输入“经度,纬度”（例如 `121.495,31.241`）后搜索，也可点击地图直接选点。填写名称，设为起点或终点。两点连线只表示直线距离。
3. “定位我”会请求浏览器位置权限并显示精度。远程使用要求 HTTPS；本机 `127.0.0.1` 可用。权限拒绝或系统定位失败时，可以继续使用坐标和地图选点。
4. 搜索“城市＋地址”需启动助手后端，显式点击搜索才访问公共 OSM / Nominatim。公共服务或网络不可用时会提示，坐标选点不受影响。
5. 设好两点后点“用这两个地点创建草稿”。经纬度、时间和来源随草稿保存及导出；手动修改任务的起终点名称会解除对应坐标绑定，避免旧坐标跟着新名称走。
6. 备降余量面板的“方案”可浏览码道版本的 5 条历史演示方案，比较检查项、航线和余量。它们不会替换当前任务或规划真实目的地。
7. 事件流支持滚动、展开、过滤和自动跟随；滚动查看时暂停跟随，新事件通过未读按钮提示。右侧问号提供三步引导；设置里可减少动画。

图层菜单可隐藏全部演示叠加或启用全球 DEM。底图保留原 CARTO 样式及来源署名；网络不通时显示离线状态和重试按钮。地图瓦片、字体及全球 DEM 依赖外网，不需要在前端填写模型密钥。

## 接收 M4 遥测

后端从 AERIS_TELEMETRY_FILE 指定的 NDJSON 文件读取最近的完整帧。M4 可以持续写入现有 ExecutionObservation，或者用下列采集器直接接收 PX4 SITL 遥测。文件在采集端和控制台后端之间共享，每帧一行。M4 的 FakeExecutor 输出会被过滤。

确认 PX4 在容器内运行后，从仓库根目录启动采集器。现有容器的 /work 对应宿主机 E:\px4。

```powershell
docker cp ops/sitl/stream_telemetry.py px4:/tmp/aeris-stream-telemetry.py
docker exec px4 python3 -u /tmp/aeris-stream-telemetry.py /work/aeris-sitl-telemetry.ndjson
```

在另一个 PowerShell 从仓库根目录启动控制台。

```powershell
$env:AERIS_TELEMETRY_FILE = 'E:\px4\aeris-sitl-telemetry.ndjson'
Set-Location apps/console
npm.cmd run dev:all
```

打开 <http://127.0.0.1:5174/?telemetry=live>，或使用顶栏的遥测切换按钮。仪表、助手和导出使用同一采样帧。缺少的读数显示为「—」，连续 5 秒没有新帧时标记已过期。有效的 WGS84 位置会更新地图标记。接收到局部 NED 或 ENU 时，默认显示带无人机图标的局部轨迹，可切换回真实底图。点「遥测明细与趋势」查看最近 60 秒的地速与俯仰，以及分组读数。采集器只订阅遥测，场景与备降余量剖面仍是示例。

## 已实现

- 地图工具栏「终端地图」把虚拟 ENU 场景渲染成 ASCII 航图，字符表示建筑、限制区、航线与备降点，`@` 跟随回放时间轴。再次点击可回到地图视图。也可用 `?map=terminal` 直接打开。
- 顶部「本地任务联调」：选择固定场景、复核参数后运行真实 M3/M2/校验器，读取 M4 合成执行的 ACK、版本、状态和审计。支持进程内直连与本地 MQTT，操作见 [`services/api/README.md`](../../services/api/README.md)。不连接 PX4，不把真实地图草稿自动转为模拟坐标。
- 联调面板有当前任务时，打开调度助手问「这单现在到哪了？」可查看同一任务的 ID、航线版本、ACK 和合成执行状态。

- 真实地理底图上的二维/三维相机、演示建筑体块、限制区、备降点、发光航线、进度与移动无人机。原有地形网格、等高线、河流示意保留在独立“地形实验”视图中。
- 电池百分比、电压、电流、能量、高度、地速、升降速、航向、RSSI、卫星数、HDOP、链路延迟、俯仰、横滚、四电机RPM、电机温度与电流波形。
- 独立的感知与搜索组件：覆盖率、已扫描/总网格、目标距离、前方障碍距离。
- 航线进度回放、暂停/继续、拖动时间轴、备降余量示例与对照曲线、事件记录、JSON快照导出。
- 五组组件可隐藏/唤起，图层可单独开关。布局、视角和本地草稿保存在浏览器 localStorage；草稿不会提交后端或控制飞机。
- 抽屉面板、键盘焦点约束、窄屏布局、减少动态效果偏好适配。
- DEM补丁导入、可选WebSocket地形流、版本校验、增量高差检测、变化区域高亮与事件记录。默认变化阈值为2米。

## 数据来源与边界

航线、建筑平面、限制区、备降点来自仓库 `scenarios/v0/` 和 `planner.astar` 的 S1-01 几何基线：266个航点、20栋建筑、4处备降点；界面展示两处限制区。坐标为3×3km的虚拟局部ENU场景，不对应现实城区。路线约3.67km，仅代表几何规划结果。

回放模式使用演示仪表。实时模式使用配置的 M4 或 PX4 SITL 遥测，导出保留采样时间和来源。初始地形、建筑高度、感知参数、余量曲线和回放事件均为演示数据。正式 M3 任务与华为云联调待完成。**演示参数和曲线仅供界面展示。**

真实地图沿用码道前端的 CARTO Dark Matter 样式（`https://basemaps.cartocdn.com/gl/dark-matter-gl-style/style.json`）和上海显示锚点 `[121.4737,31.2304]`。本地 ENU 几何经过显示换算叠加，**没有测绘配准，不代表该位置的真实建筑、限制区或可飞航路**。定位到其他城市不会把这些演示对象搬过去。可关闭演示叠加只看真实底图。

历史方案快照 `public/codearts-review.json` 摘自本机码道前端 `apps/web/assets/scene.js`，保留各方案版本、检查与剖面；其中数值都是构造的演示数据，未经当前校验器复算，不是评测结果。仓库主分支的旧 `apps/web` 页面与本机工作区码道版本可能不同，本次仅提交快照，不覆盖队友源码。

可选全球 DEM 来自 Mapzen / AWS Open Data Terrarium 公共瓦片，是已有高程资料，**不提供现实地形实时变化感知**。DEM 数据补丁及原地形实验使用另一套局部演示网格。地理目的地草稿尚未连接真实空间规划器；助手的 A\* 预览仍只接受已登记的局部演示地点，不能把真实选点的直线当成安全航线。

“地形变化识别”当前是收到高程数据后进行相邻版本比对，不是通过页面自行感知现实环境，也没有实现视觉/激光SLAM。需要传感器、测绘服务或后端提供同一坐标/高程基准的DEM。地形变化不会自动修改已规划航线，不会自行触发飞控指令；重规划与安全校验需要后端完成。静态道路、河流与建筑是初始场景上下文，不会随DEM自动重建。

重新导出几何场景（需要仓库Python依赖）：

```bash
python apps/console/scripts/export_scene.py
```

## 地形数据接口

打开左侧“地形数据设置”。可注入一次演示变化、每8秒自动演示、导入JSON或连接WebSocket。连接外部流时会暂停自动演示；飞行遥测仍独立标注为演示。关闭页面会释放连接。

```json
{
  "revision": 1,
  "source": "DEMO terrain adapter",
  "capturedAt": "2026-11-10T12:00:00Z",
  "mode": "delta",
  "cells": [
    { "x": 63, "y": 52, "height": 42.5 },
    { "x": 64, "y": 52, "height": 44.1 }
  ]
}
```

- `x/y`为整数网格索引0—90，**不是米或经纬度**；索引0对应局部0m，90对应3000m，间距为3000/90m。
- `height`为绝对高程值（米），必须与初始网格使用同一高程基准，不是高度增量。来源名称与采集时间必填。
- `revision`必须严格递增，网格不可重复，高程须为有限数值；单次文件/消息上限1MB。完整校验后才应用，错误补丁不会部分修改地形。
- `mode`默认`delta`。接入真实数据时，先用`baseline`发送完整91×91网格建立基准，再用`delta`发送变化；建立基准不触发变化报警。增量只影响列出的网格。
- 变化检测是每个**网格顶点**的高程差绝对值≥2m，界面计数为便于阅读称“网格”。高亮和包围框对应实际变化位置。

WebSocket消息外层增加类型：

```json
{
  "type": "terrain.patch",
  "patch": {
    "revision": 2,
    "source": "DEMO terrain adapter",
    "capturedAt": "2026-11-10T12:00:02Z",
    "cells": [{ "x": 63, "y": 52, "height": 47.5 }]
  }
}
```

本机可用 `ws://127.0.0.1:端口/terrain`，远程须使用 `wss://`。当前未实现服务端认证、自动重连、坐标重投影或跨会话地形版本持久化；这些需要与数据服务共同设计。

## 后续接入顺序

调度助手使用A键收放；模型配置与M3接入边界见上方助手说明。当前新增本地工具服务没有替代M3的正式确认、下发与ACK流程。

1. 对接遥测适配层：PX4/MAVSDK经过后端转为界面单位、时间戳及来源，增加过期/缺失提示，再替换 `useFlight.ts` 演示源。
2. 对接M3任务/事件、M2候选航线与真实备降余量剖面；保留任务版本、确认状态和审计标识，不把草稿保存当下发成功。
3. 为真实地形提供坐标、高程基准及基准帧，接入DEM增量；需要现实变化感知时再接传感器或测绘更新流程。
4. 选定部署入口后配置反向代理、HTTPS、WebSocket及身份认证。当前不需要购买云资源即可本地演示。
