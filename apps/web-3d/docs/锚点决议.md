> 阶段 0 文档。坐标系、原点与场景 v0 平移一经写入，后续阶段不得悄悄改动；若必须调整，先向用户汇报。

## 1. 锚点

**工程原点（ENU 原点）= 成都天府新区兴隆湖湖心。**

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 纬度 | **30.399075° N** | WGS84 / CGCS2000，取 6 位小数 |
| 经度 | **104.085889° E** | 同上 |
| 高程 h0 | **474 m**（暂定） | 见第 1.3 节 |
| 代码常量 | `src/geo/enu.ts` 中的 `ANCHOR` | 环境变量 `VITE_ANCHOR_LAT` / `VITE_ANCHOR_LON` / `VITE_ANCHOR_H` 同步预留 |

### 1.1 来源与取位

原始查询来自 OpenStreetMap 水域关系 **relation 6959413**（名称：兴隆湖；分类：`water/lake`），经 Nominatim 搜索接口返回的代表点（水体多边形的代表中心，非岸线某一点）：

- 原始值：`lat = 30.3990752`，`lon = 104.0858889`
- OSM：<https://www.openstreetmap.org/relation/6959413>
- Nominatim 查询（2026-11-10 检索）：<https://nominatim.openstreetmap.org/search?q=%E5%85%B4%E9%9A%86%E6%B9%96&format=jsonv2&countrycodes=cn>
- 许可：© OpenStreetMap contributors，ODbL 1.0

同一关系的外包框为 `lat 30.3910773–30.4069834`，`lon 104.0724926–104.1000005`，与 topographic-map.com 公布的兴隆湖图幅范围（30.39113 104.07249 30.40685 104.09964，<https://zh-cn.topographic-map.com/map-m6lt1h/兴隆湖/>）一致，可交叉印证该关系确为天府新区兴隆湖，而非其它同名水体。

**精度取 6 位小数**（纬度约 0.11 m，本纬度经度约 0.10 m）。理由：

- Nominatim 代表点是岸线多边形的几何中心，岸线数字化本身就有米级不确定性，再保留 7 位（厘米）没有工程意义；
- 6 位已优于阶段 4「地标落图误差 < 5 m」的对图预算，也足够作为 ENU 原点写入环境变量。

工程采用的舍入：`30.3990752 → 30.399075`，`104.0858889 → 104.085889`。

OpenStreetMap / Nominatim 使用的是 WGS84。需求文档第 5 节已说明：天地图采用 **CGCS2000，与 WGS84 近似一致**（两椭球差异在本项目尺度上远小于分米，可忽略），因此本锚点同时作为 WGS84 与 CGCS2000 坐标使用，不再做额外转换。

### 1.2 明确排除的坐标（请勿「校正」）

部分公开网页给出的「兴隆湖」坐标来自高德等国内互联网地图，属于 **GCJ-02**，相对 WGS84 可能偏移数十至上百米，**不得**用作本工程原点。例如高德地点页「兴隆湖湿地公园」公布 `30.393487, 104.080420`（<https://www.amap.com/place/B0FFGIJ63W>），与上述 OSM 湖心相差约数百米，且坐标系不符。百度坐标（BD-09）同样排除。

现有单文件 demo（`public/legacy/demo-baseline.html`）里的「成都 104.0668°E, 30.5728°N」已自行标注为**示例锚点**，位置偏在成都市区而非兴隆湖，本决议予以作废，仅作历史对照。

### 1.3 高程（暂定，待测）

水平原点已定；垂直基准尚未实测。现阶段：

- h0 = **474 m**，取自 topographic-map.com 兴隆湖图幅「平均海拔 474 米」（正高 / 近似海拔，<https://zh-cn.topographic-map.com/map-m6lt1h/兴隆湖/>）；
- 转换模块把该值**当作椭球高**使用。成都一带大地水准面差距约数十米，因此当前 h0 与真正的 WGS84 椭球高并不相等；
- **对阶段 0 的往返测试与水平落图没有影响**（往返用同一 h，相对高差仍正确）；
- 正式椭球高（以及是否改用 1985 国家高程基准的正高）留待有 RTK / 水准数据后再替换 `ANCHOR.h` 与 `VITE_ANCHOR_H`，需另行记录，不在阶段 0 擅自修改水平锚点。

## 2. 为何选天地图（及 ion 的授权限制）

需求文档第 5 节已查证拍板，此处只把决议写死，不重新选型。

1. **坐标系**：天地图（CGCS2000）与 WGS84 近似一致，**没有**高德 / 百度的 GCJ-02 加密偏移（偏移可达几十至上百米）。低空航线对地精度以米计，GCJ-02 方案直接排除。
2. **成本与接入**：浏览器端应用可免费申请 token；WMTS 瓦片（影像 `img_w`、矢量 `vec_w`、中文注记 `cia_w`）接入 Cesium 的路径成熟。
3. **Cesium ion Community（免费）只作增强**：世界地形 + OSM 建筑 3D Tiles（asset 96188），约 15 GB/月流式额度，演示够用。Google 写实 3D Tiles 需绑卡按量计费，不用。
4. **授权限制（必须遵守）**：ion 免费档为**社区授权（Community）**，仅限非商业 / 评估用途。本项目当前用于华为 ICT 大赛演示与后续真机实验准备，阶段 0 按社区授权使用；若日后转为商业部署，必须另行购买商业授权或去掉 ion 层，只保留天地图底图。不得把社区 token 用于商业产品。
5. **阶段 0 现状**：天地图 token 与 Cesium ion token 需用户自行注册申请（本阶段未注册、未付费）。未拿到 token 前，底图与地形加载属于「待 token」，不阻塞脚手架、demo 存档、本决议与 ENU 转换测试。

## 3. 场景 v0 的口径与平移

### 3.1 fork 口径（不要与上游混用）

与需求文档第 4 节、第 7 节红线一致：

- 场景范围：**3000 × 3000 m**，场景坐标 x 向东、y 向北，单位米；
- 限制区 **R01 = (1000, 1200)–(1400, 1700)**（上游常见口径是 (1300,1300)–(1700,1700)，勿用）；
- 规划器净空 **20 m**（上游常见 30 m，勿用）。

### 3.2 场景原点放在哪里（已确认）

**选定：3000×3000 m 区域的几何中心 (1500, 1500) 对准兴隆湖湖心。**

即：

- ENU 原点 = 锚点（湖心），e 东、n 北、u 天，单位米；
- 场景坐标与 ENU 的关系：

  ```
  e = x − 1500
  n = y − 1500
  u = z          （z 为相对锚点椭球高的高度，米）
  ```

- 代码：`sceneToEnu` / `enuToScene`（`src/geo/enu.ts`）。用户已于 2026-11-10 确认该方案。

**理由：**

1. 兴隆湖 OSM 外包框相对湖心约西 1283 m、东 1351 m、南 890 m、北 880 m。把场景中心放在湖心后，场景覆盖 ENU `[-1500, 1500] × [-1500, 1500]`，**整湖都落在场景内**，西岸、东岸都有余量。
2. 若改用「场景 (0, 0) 对准湖心」，则整个 3000×3000 区域只覆盖湖心东北象限，湖面大部分和西岸（地铁兴隆湖站一带）都会落在场景外，演示和对图都会缺一块。
3. 平移后 R01 的 ENU 范围为 **(-500, -300)–(-100, 200)**，落在湖心偏西、略跨南北的水域上，作为 v0 限制区几何可以接受（v0 本就是虚拟场景贴到真实地理，不要求 R01 对应某一块真实禁飞区）。

场景四角的地理含义（近似，便于对照）：

| 场景坐标 | ENU (e, n) / m | 相对湖心 |
| --- | --- | --- |
| (0, 0) | (−1500, −1500) | 西南角 |
| (3000, 0) | (1500, −1500) | 东南角 |
| (0, 3000) | (−1500, 1500) | 西北角 |
| (3000, 3000) | (1500, 1500) | 东北角 |
| (1500, 1500) | (0, 0) | 湖心（锚点） |

后续阶段 4 把虚拟场景「按锚点平移到真实坐标」时，一律走 `sceneToEnu` → `enuToLla`，不要另写一套平面公式。
