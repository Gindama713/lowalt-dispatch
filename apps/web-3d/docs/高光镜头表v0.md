# 高光镜头表 v0（3D 展厅 · 参赛视频核心镜头）

> 阶段 1 交付物。镜头 = 验收标准：每段镜头写清**时长、机位路径、动作时序、缓动、字幕点**，动作全部引用 `assets-src/parts-v1.json` 的部件 id 和 `explode` / `fx` / `unfold_timeline` 字段。
> 机器可读版：`assets-src/blender/shots_def.py`。Blender 动态预演（animatic）和逐帧穿模回放都调用它，所以三处用的是同一份数据。
>
> **验收边界（必须分清）**
> - **阶段 1 只验证两件事**：镜头设计（机位、时序、字幕点）和**骨架级无穿模**（方盒/圆柱骨架，在每个动画帧上做网格求交检测）。
> - 浏览器 ≥50/60 fps、无闪烁、1080p 以上录制、Bloom/景深/ACES 等实时画面效果，都属于**阶段 3「首页 3D 展厅」的实时渲染验收**。阶段 1 **没有达成、也不宣称达成**这些。
> - 预演是 Blender Workbench 快速离线渲染的骨架（按系统着色，Studio 光 + 阴影 + 腔体）。冰蓝眼部和金属黄扫光是用每帧单独渲染的自发光遮罩，在合成时叠加高斯辉光模拟出来的。方块造型和光照都不代表最终效果。
> - 为什么不用 Cycles：Cycles 4 spp 在本机约 5.5 s/帧，与其他渲染任务争用 CPU 时会降到约 30 s/帧，4 段共 720 帧要好几个小时，所以预演改用 Workbench。PBR 质感请看 `hero_pbr_preview.png` 和转台视频（Cycles）。

坐标：机体系，x 前、y 左、z 上；本表机位单位为 **mm**（`shots_def.py` 里用米）。焦距按全画幅（36 mm 胶片宽）计算。帧率 24 fps（预演）；阶段 3 实录目标 60 fps。

## 骨架级穿模检测（阶段 1 验收项）

- 脚本：`assets-src/blender/check_v1.py`。每个部件网格内缩 0.5 mm 后建 BVH，做两两三角面求交，再用三方向射线奇偶多数表决判断“完全包含”。父子件和已声明的安装接触面（`contacts`）不算穿模。
- 检测覆盖：S1–S4 每个 24 fps 帧；展开时序另做 120 Hz 细采样；爆炸/复原整条时间轴；云台三轴 595 组姿态；舱门 0–100°；旋翼 0–180°。
- 检测器自检：故意把相机推进配送箱，并把一个小件塞进电池内部，这两种情况都必须报出来，用来证明检测器不是一直报 0。
- 最新结果见 `_shots/stage1/check_report_v1.json`（`collision_states`、`collision_total`、`detector_selftest`）。

## 阶段 3 实现对照（R3F）

| 镜头字段 | R3F 实现 |
|---|---|
| 机位路径 / 焦距 | GSAP timeline 驱动 `camera.position`、`camera.fov`（fov = 2·atan(12/焦距)，单位 rad）；`target` 用 drei `CameraControls.setLookAt` |
| `unfold_timeline` | 按 `steps[].t/dur/ease` 生成 GSAP tween，作用在节点 `quaternion`（转轴 = `pivot.axis`，转换到 Y-up 坐标） |
| `explode` | `position = rest + vector_mm/1000`（父件相对），delay/duration/ease 直接读 JSON |
| `fx.light` | 材质 `emissiveIntensity` 动画；Bloom 阈值只放行 emissive |
