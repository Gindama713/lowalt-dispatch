### 1.2 `POST /tasks`

- **状态：** 已实现。  
- **源码：** `main.py`  
- **成功：** 201，响应体即校验后的 `Task`  
- **请求体：** `core.models.Task`，`extra=forbid`。字段见 [`接口契约.md`](接口契约.md) §2.1，不在此重复。

HTTP 比契约多出的约束：`task_id` 不能为空、不能含 `/` 或 `\`，否则 422。重复 ID 为 409。本层不检查 `vehicle_type` 是否真有机型文件。

```json
  "destination": {"frame": "enu_m", "x_m": 2650, "y_m": 2750, "alt_m": 30, "alt_ref": "rel_takeoff"},

  "vehicle_type": "placeholder",
  "initial_energy_wh": 100,
  "reserve_energy_wh": 20,

    "source": "demo",
    "version": "0",
    "captured_at": "2026-11-09T00:00:00+00:00",
    "is_simulated": true

```

**错误码：**

| 码 | 条件 |
|---|---|
| 201 | 创建成功 |
| 409 | `任务 {task_id} 已存在` |
| 422 | task_id 非法；或 Pydantic 校验失败（坐标混用、缺字段、多余字段、能量不满足约束等） |

`initial_energy_wh: 100` 只是任务单上的数。默认规划器不算能耗，接口不会把它抄进 `energy_budget_wh`。

### 1.6 `POST /tasks/{task_id}/snapshots`

- **状态：** 已实现。  
- **源码：** `main.py`  
- **成功：** 201，回传 `RiskSnapshot`

#### 1.10.2 `AgentHookResult`（`envelopes.py`）

| 字段 | 类型 | 说明 |
|---|---|---|

**默认入口下的结果特征（已用测试核实，不是编造的业务数字）：**

- 用 S1-01 起终点、未点名限制区：`found=true`，航程与直接调用 `plan_scenario` 一致；`route=null`，`route_plan_status=unavailable`；`margin_status=unavailable`，`margin_profile=null`。
- 用 S4-04 起终点且快照点名 R04：`found=false`，`reason` 来自规划器（含“终点”）。
- 同一对起终点若不点名 R04，则可能找到路线。
- `agent.status=not_implemented`（未设 `AGENT_ENTRY`）。

**错误码：**

| 码 | 条件 |
|---|---|
| 200 | 无论找到或未找到路线（无解也是 200，看 `found`/`reason`） |
| 400 | `任务还没有快照。先加载场景或提交 RiskSnapshot，再规划。` |
| 404 | 任务或指定 snapshot 不存在 |
| 409 | `快照 {id} 已过 valid_until，不能用来规划新路线。` 此时不存路线 |
| 422 | 起终点坐标系/高度基准不一致；非 ENU；缺平面坐标；快照时间无时区 |

1. **已知问题：** 默认 `PLANNER_ENTRY` 是 `planner.astar:plan_scenario`。不判时限、不算能量、不做备降剪枝。`margin_status=unavailable`，`margin_profile=null`。`GET .../margin` 的 `profile`、`min_margin_wh`、`negative_sample_count`、`is_feasible` 均为 null。  
2. **已知问题：** 默认入口不产出 `RoutePlan`。缺 `energy_budget_wh` 时接口不把 `initial_energy_wh` 抄进去。`route=null`，`route_plan_status=unavailable`。  
3. **已知问题：** `PLANNER_ENTRY=planner.diversion:plan_scenario_with_diversion` 会 HTTP 500。缺 `vehicle`（「规划入口参数无法填充：vehicle」）。即便补上参数，`ScenarioPlan.profile` 也不在适配层识别的属性名里，返回值类型也无法识别。见 3.2。  
4. **已知问题：** 请求体 `algorithm` 不切换引擎。测试 `test_requested_algorithm_name_does_not_switch_planner` 要求实际仍是 `astar_static`。  
5. **已知问题：** `astar_dynamic` 是 `MockPlanner`。禁止把数字接到 HTTP 或材料。  
6. **未实现：** 没有 WebSocket、MQTT 客户端、`/verify`、下发、遥测、回放。契约 §3 这些行仍是仅规划。  
7. **未实现：** fork 无 `validator/`。评测里的 `hard_constraint_report` 与规划器共用距离场，不是独立校验。上游校验器见第 7 节。  
8. **未实现：** 真实机型参数仍为 null。示例机型只能显式用于评测 CLI。  
9. **已知问题：** 存储是 SQLite 或内存。PostgreSQL / Redis 的 `connected` 在 `main.py` 里恒为 `false`，配了 DSN 也不连接。OBS 与华为云部署未实现。  
10. **未实现：** M3 状态机。fork 只有 hook，默认 `not_implemented`，`applied` 恒 false。  
11. 契约 §3 与代码不一致时以代码为准，差异见第 0 节。字段表以 [`接口契约.md`](接口契约.md) 为准，本文不另写一套。
