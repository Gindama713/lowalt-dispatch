# 真实航线实现与验收

实现位置：`E:\ICT大赛\lowalt-dispatch`。`lowalt-console-ui` 是另一个有用户未提交修改的工作副本，本次没有改动它。冻结的 `scenarios/v0` 不变。

## 使用

启动方式沿用项目《启动指南》。从工单进入 `/airspace?intake=<id>`，页面自动读取真实起终点、工单起飞时刻并请求真实规划。地图选点后也可点击“计算真实避障航线”。结果提供 WGS84 航点、建筑与道路快照、天气来源、估算标识、警告和 JSON 导出。

真实视图隐藏原有仿真任务卡、仪表、固定剩余航时和演示回放。修改或清空起飞时刻时明确提示旧预报需要重新计算；修改端点则取消请求并清除原结果。原 ENU 演示入口保留，用于回归验证，不当成真实地图或飞行参数。

```http
POST /api/assistant/navigation/candidates
Content-Type: application/json
X-Aeris-Request: 1
```

```json
{
  "frame": "WGS84",
  "origin": {"lng": 121.335209, "lat": 31.197950},
  "destination": {"lng": 121.804400, "lat": 31.144383},
  "scheduled_for": null,
  "resolution_m": 10,
  "max_expand": 500000
}
```

需已登录会话。`scheduled_for` 为空时使用查询时刻；填写时必须含时区。真实任务限制为 10 m–80 km 的局部区域。`GET /api/assistant/navigation/scenes/{scene_id}` 读取本次规划使用的建筑、道路与来源快照；标识严格校验，过期快照拒绝读取。

`available` / `geometric_available` 仅代表建筑二维几何路径可用。`operationally_approved` 始终为 false，`dispatch_enabled` 始终为 false。WGS84 规划在 `AERIS_FLYSAFE_LIVE` 未关闭时会按起终点外扩范围查询大疆 FlySafe，并把结果绑定为约束快照。`airspace.reference_label` 为「大疆 FlySafe 厂商地理围栏参考」时，只表示用了这次厂商围栏快照；`passed_known_snapshot` 只表示通过本次已知区域检查，不是 UOM / 国家地图官网 / 天地图，也不是飞行批准。规划快照里的禁飞区在地理底图上是红色填充，坐标保持 WGS84。若已经有一次成功的厂商围栏，之后的瞬时查询失败会保留那些区域，`source_status` 仍为 `manufacturer_reference`，`failure_reason` 说明本次刷新失败。没有上次成功几何时，查询失败或空结果的 `source_status` 为 `unavailable`，没有几何，不是放行。未查询时仍可能是 `manual_review_required`。机场起终点不会因为名字或演示需要获得通行判定。

请求体可带 `"include_flysafe": true`（控制台计算航线时会带上）。`POST /api/assistant/airspace/flysafe` 用同一规则刷新当前工作区快照，区域数超过 100 会失败关闭、不截断冒充完整快照。全国显示不走这条快照：`GET/POST /api/assistant/airspace/flysafe/national` 只读写地图叠加和本地缓存 `logs/flysafe-national/china.json`（或 `AERIS_FLYSAFE_CACHE_DIR`）。查询矩形是西 73.5°、南 18.0°、东 135.1°、北 53.6°，由 `dji-geo` 自动切块去重；单次 HTTP 超时 30 秒。分块失败不补几何，响应 `incomplete=true`，文案写明本次刷新不完整。整次失败则继续返回上次成功缓存。这层全部涂成同一种红色，不参与硬避让。硬避让仍只有规划快照中的禁飞 / 法规限制类。浏览器测试进程设置 `AERIS_FLYSAFE_LIVE=0`，不访问大疆网络。

## 真实地图和保守避障

优先查询 [Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API)，建筑包括 way、building:part 和 multipolygon relation，道路读取 highway。全球 Overpass 镜像无法连接时，在明确请求数和网络时间预算内使用 [OSM 官方 API 0.6 map](https://wiki.openstreetmap.org/wiki/API_v0.6#Map:_GET_/api/0.6/map) 分块获取同一范围；来源字段如实区分两个接口。两者均不可达时返回 HTTP 503，不返回仿真建筑或默认直线。

完整快照写入 `scenarios/real/<bbox-hash>/obstacles.geojson`、`roads.geojson`、`metadata.json`，含原始标签、OSM 对象链接、抓取时间、覆盖 bbox、版权及高度来源。有效期默认 24 小时，过期不在断网时静默沿用。`.tiles/` 是可续传的临时原始传输缓存，单独忽略；完整快照才作为规划数据。

高度依次读取 `height`（支持米/英尺）、`building:levels × 3 m`。3 m 层高属于明确估算；两类标签都没有时返回 `height_m: null`，不会补默认建筑高度。全部建筑按水平足迹绕行，不因已知高度、未知高度或楼层推算而允许越顶。道路只作地理参照，不表示飞行走廊或可用起降场。

若完整真实节点存在但 OSM 环拓扑错误，允许用全部原始节点的凸包形成保守不可通行包络，标记 `geometry_status: derived_conservative`、保留来源和警告。网络缺失节点或未取得成员时仍失败，不借几何修复掩盖数据缺失。

坐标使用独立 `planner/georef.py` 局部等距圆柱投影，以航路中点建立米制参考系，不使用前端 `DEMO_ANCHOR`。真实网格由端点包围框外扩 1 km，且严格限制在已下载地图 bbox 中。接口默认分辨率 10 m，物理净空 20 m，栅格排除半径 `20 + resolution_m / sqrt(2)`。这里直接测量网格中心到真实几何的距离，相邻中心间任意点离最近中心最多半个对角线；距离函数的 1-Lipschitz 性质保证整个网格边的物理净空。精确端点另用连续几何检查连接段，最终所有输出线段再独立检查。20 m 粗网格在本次密集建筑带会阻断航路，10 m 实测能在 30 s 内规划，因此选用实测通过的 10 m。原 v0 的 10 m / 30 m 参数保持不变。

新真实规划使用加权 A*，启发权重 1.50，扩展数和整个几何处理时间均有上限；不声称严格最短。此选择按真实机场任务实测减少搜索量，以少量额外绕行为代价提供计算时间余量，参数会在接口和证据中返回。投影、栅格化、搜索、简化和最终复核共用 28 s 预算，超时不发布未完成校验的结果。输出前用连续线段几何独立检查水平净空，只有替代线段完整满足净空才简化航点。精确保留输入起终点；端点在建筑或 20 m 物理净空内直接拒绝。满足物理净空但落入保守栅格屏蔽时，可输出一段经过连续几何检查的端点连接段，不偷偷移动端点。

OSM 志愿者地图可能漏绘或过时，真实地图不等于障碍调查。地形、线缆、塔吊、移动障碍和官方空域尚未形成完整核验数据。大疆 FlySafe 只补充厂商设备地理围栏参考，不填补上述缺口。

## 天气与实机参数

详见《真实航线天气与能耗.md》。航线天气沿球面弧长等距采样，45 km 为 24 点；`forecast_days=2`，更晚的起飞日用 `start_date`/`end_date`。每个采样点按自己的到达时刻取预报。没有标定空速、有来源的厂家参考速度或调用方显式假设空速时，ETA 保持不可用。`independent_cells` 只统计返回的 `model_point`，缺失时为 null。缺测或超出预报窗口不填默认值。

风三角按各采样段的真实航向迭代到达时刻，最多 5 轮，收敛判据严格小于 5 秒。安全侧看覆盖时段内的阵风最大、降水最大和能见度最小。顺逆侧风敏感性表仍固定航向 90°，只作演示。温湿度对空气密度和理想旋翼诱导功率的影响仍在。仓库没有真实标定机型，故没有标定空速时不编造 ETA；厂家目录里有来源的参考速度可以标成 `manufacturer_reference`，但 Wh 仍不可用。不能借合成机型或任意电池低温系数填空。P2 因素矩阵和 verdict 引擎尚未实现。

后续已增加“配送机型库”（`/aircraft`）：三款官方规格可供选择、按实际绕障长度对照载荷和参考航程；用户也可手动录入和导入自己的参数，主动运行独立的 `user_test` 时间/能耗测试。此类条件测试与实机验证状态独立，详见《配送机型库与测试.md》。厂家规格未补充虚构 Wh/m。

独立真实数据审计工具（在仓库根目录运行，无默认演示起终点）：

```powershell
.venv/Scripts/python.exe -m tools.verify_real_route --origin 121.335209,31.197950 --destination 121.804400,31.144383 --output results/real_route_probe.json
```

输出包含联网来源、地图数量、五栋建筑原始标签与高度转换核对、实际规划耗时、逐段净空复核、真实天气结果及不可下发标识。测试夹具只验证算法和接口，不作为真实数据证据。

本次已使用上述原始机场坐标成功验证：直线 **45,035 m**，绕障航程 **50,994 m**，**97 航点**，搜索 **57,697 节点**，几何规划约 **5.29 s**，独立连续净空最小 **20.1236 m**。`results/real_route_probe.json` 的七项审计全部通过；含缓存读取、天气和独立审计总耗时约 **9.01 s**。同次重新请求的三处天气均为真实成功预报，实际机型能耗仍明确 unavailable。`results/real_navigation_api_probe.json` 另存实际已登录浏览器请求真实候选航线接口的结果，包含当次规划耗时、航点及来源；耗时随机器负载和上游网络变化。另一次页面验证在软件地图渲染负载下几何规划为 **21.69 s**，天气服务不可达，完整结果保存为 `results/real_navigation_weather_unavailable_probe.json`；页面和接口均明确显示 unavailable，没有补默认天气。

`results/real_route_20m_probe.json` 保留20 m网格未找到路径的真实对照结果。`results/real_reference_route_probe.json` 是另一个独立指定坐标的真实长距离参考任务，不用来替代或冒充机场任务成功。

浏览器额外提供显式联网验证，可独立运行；常规测试默认跳过，避免把外部服务可用性作为离线单测前提：
